# 4대보험 취득·상실 자동화 MVP

## 목표
현재 동행솔루션 세무 AX 안에 4대보험 업무를 독립 모듈로 추가한다.
사용자는 사업장과 직원 정보를 등록하고 취득/상실 요청을 생성한다. 시스템은 필수값을 검증하고 담당자 승인 이후 전자신고 제출대기 상태로 넘긴다.

## 제품 원칙
1. 하나의 서비스 안에서 공통 사업장/직원 데이터를 사용한다.
2. 4대보험은 별도 업무 모듈로 분리한다.
3. 공동인증서 원본과 인증서 비밀번호를 데이터베이스에 저장하지 않는다.
4. 실제 기관 제출은 공식 API/EDI/업무대행 구조를 우선한다.
5. 기관 자동화가 필요하더라도 브라우저 RPA는 trusted worker에서만 실행하고 클라이언트 브라우저나 Supabase 테이블에 인증비밀을 남기지 않는다.
6. 모든 요청/승인/제출/결과 변경은 감사로그 대상으로 한다.

→ 처리결과 확인

## DB
이번 MVP에서 추가하는 테이블은 다음과 같다.

- `employees`: 사업장 직원 마스터
- `insurance_requests`: 취득/상실/변경 요청
- `insurance_submissions`: 외부 전자신고 제출 및 응답 기록
- `insurance_delegations`: 업무대행 위임 상태

상세 스키마는 `supabase/insurance_automation_mvp.sql` 참조.

## 인증/자동화 구조

### 금지 구조
고객 인증서 파일 + 인증서 비밀번호
→ Supabase DB 저장
→ 브라우저 JS가 읽음
→ 기관 사이트 자동 로그인

이 구조는 사용하지 않는다.

### 목표 구조
사용자 요청
→ Supabase 요청 DB
→ 담당자 승인
→ trusted server/worker
→ 공식 전자신고/API 또는 허용된 업무대행 채널
→ 접수번호/처리결과만 DB에 저장

인증이 필요한 자동화가 불가피한 경우에도 인증비밀은 별도 secret store/HSM/OS credential vault 등 서버 전용 보안영역에서 관리하고, 평문 비밀번호를 애플리케이션 DB에 넣지 않는다.

## MVP 개발 순서

### Phase 1 — 내부 업무흐름
- 직원 마스터
- 취득/상실 요청 생성
- 필수값 검증
- 담당자 승인
- 상태관리
- 감사로그

### Phase 2 — 신고자료 생성
- 취득/상실 신고 payload 생성
- 보험별 필수값/예외 규칙
- XLS/XLSX 또는 EDI 호환 출력이 가능한 경우 출력 어댑터

### Phase 3 — 기관 연계
- 공식 API/EDI 연계수단 조사 및 계약/권한 확인
- 업무대행 위임 상태 연결
- trusted worker 제출
- 접수번호 저장

### Phase 4 — 결과 자동수집
- 처리상태 주기 조회
- 반려 사유 수집
- 고객/담당자 알림
- 보완 후 재제출
